## 5. אילוצים

- **אחסון סטטי בחינם, למשל GitHub Pages.** אין שרת משלנו. **[החלטה שלך: דרך א']**
- **בלי ספריות ובלי framework**, ובלי שלב build. רק קבצי HTML, CSS ו-JavaScript רגילים. היעד הוא שהאתר כולו ישקול בערך 10–15KB. **[הצעה שלי, חלק מדרך א']**
- **מקור הנתונים:**
  - **MusicBrainz** הוא המקור לז'אנרים, ללהקות, לאלבומים ולשירים. **[החלטה שלך]**
  - **ListenBrainz** הוא המקור לנתוני פופולריות (מספר האזנות). הוא של אותו ארגון ומשתמש באותם מזהים. **[הצעה שלי]**
  - שני ה-API חינמיים ולא דורשים הרשמה, לפחות לפי מה שמצאתי.
- **מגבלת קצב של MusicBrainz:** בממוצע בקשה אחת בשנייה לכל כתובת IP. בקשות מהירות יותר נחסמות עם שגיאה 503.
- **ממשק בעברית ומימין לשמאל.** שמות הלהקות, האלבומים והשירים מוצגים באנגלית, כמו שהם. **[הצעה שלי]**
- **מה אומת בקוד המקור של ה-API (2026-10-31):**
  - **MusicBrainz** מאפשר פנייה ישירה מהדפדפן. כל ה-controllers של `ws/2` כוללים את `Role::CORS`, ששולח `Access-Control-Allow-Origin: *` ועונה לבקשות preflight. נמצא ב-`metabrainz/musicbrainz-server`, בקבצים `lib/MusicBrainz/Server/ControllerBase/WS/2.pm` ו-`Controller/Role/CORS.pm`.
  - **ListenBrainz** מאפשר פנייה ישירה מהדפדפן. ה-decorator `@crossdomain` שולח `Allow-Origin: *`, מתיר את `Content-Type` ועונה ל-OPTIONS.
  - **אילו בקשות של ListenBrainz דורשות מפתח:**
    - `top-recordings-for-artist`, `top-release-groups-for-artist` ו-`lb-radio` **דורשות מפתח גישה**. הן קוראות ל-`ensure_user_token_for_expensive_endpoint` "בגלל סורקי AI".
    - בקשות ה-**batch** **לא דורשות מפתח**: `POST /1/popularity/artist`, `/release-group` ו-`/recording`. כל בקשה מקבלת עד 1000 מזהי MBID ומחזירה `total_listen_count` ו-`total_user_count`.
    - **לכן משתמשים רק בבקשות ה-batch.**
  - **מה עדיין לא נבדק:** אף בקשה לא נשלחה בפועל, כי סביבת הפיתוח חוסמת את הדומיינים. גם המבנה המדויק של התשובות לא נבדק, ולא נבדק מה באמת חוזר מחיפוש שירים לפי תגית.

## 9. המתכון מפרויקטים קיימים (מחקר מ-2026-10-31)

**מה לא נמצא:** חיפשתי שיחות משותפות ו-Artifacts של Claude, ChatGPT ו-Gemini שמשתמשים ב-MusicBrainz או ב-ListenBrainz, ולא מצאתי. מנועי החיפוש לא החזירו אף דף כזה. בנוסף, claude.ai ו-chatgpt.com חסומים מסביבת הפיתוח, אז לא יכולתי לחפש בהם ישירות. כל הדוגמאות בסעיף הזה הן מקוד פתוח ב-GitHub.

### 9.1 תור בקשות ל-MusicBrainz (בקשה אחת בשנייה, וניסיון חוזר על 503 ו-429)
מתוך [fernandofilter/disco-da-vez](https://github.com/fernandofilter/disco-da-vez/blob/HEAD/src/lib/musicbrainz.ts), אתר שמגריל אלבום לפי ז'אנר ופונה ל-MusicBrainz ישירות מהדפדפן:
```ts
let lastCall = 0
let chain = Promise.resolve()
function mb(path, params) {
  const qs = new URLSearchParams({ fmt: 'json', ...params })
  const run = async () => {
    for (let attempt = 0; attempt < 4; attempt++) {
      const wait = lastCall + 1050 - Date.now()
      if (wait > 0) await sleep(wait)
      lastCall = Date.now()
      const r = await fetch(`https://musicbrainz.org/ws/2${path}?${qs}`, { headers: { Accept: 'application/json' } })
      if (r.ok) return r.json()
      if (r.status !== 503 && r.status !== 429) throw new Error(`MusicBrainz ${r.status}`)
      await sleep(2000 * (attempt + 1))
    }
    throw new Error('MusicBrainz overloaded')
  }
  const p = chain.then(run); chain = p.catch(() => {}); return p
}
```

### 9.2 אלבומים לפי ז'אנר
גם זה מתוך disco-da-vez.
- **השאילתה:** `tag:"thrash metal" AND primarytype:album AND status:official` על `/release-group`.
- **ספירה:** קודם מבקשים `limit=1` כדי לקבל `count`, ושומרים את התוצאה בזיכרון.
- **מגבלה:** לפי הפרויקט, החיפוש של MusicBrainz מחזיר רק את 500 התוצאות הראשונות (`offset + limit <= 500`).
- **סינון אלבומי אולפן:**
  - פוסלים כל אלבום עם `secondary-types`, כלומר Live, Compilation וכו'.
  - פוסלים אלבום בלי `first-release-date`.
  - פוסלים כותרות שמתאימות לביטוי `greatest hits|best of|anthology|unplugged|live (at|in|from|on)|...`.
- **הסרת כפילויות:** מנרמלים את הכותרת ומסירים ממנה סוגריים ומילים כמו deluxe ו-remastered, ואז משווים לפי "להקה|כותרת".
- **הבדל מהמשחק שלנו:** disco-da-vez **בכוונה** בוחר עמוד אקראי כדי "לברוח מהמובן מאליו". אנחנו צריכים את ההפך, ולכן מוסיפים שלב פופולריות (9.3).

### 9.3 סינון פופולריות בלי מפתח (להקות ואלבומים)
מתוך [Alextheguy1/FreeListen](https://github.com/Alextheguy1/FreeListen/blob/HEAD/frontend/index.html) ו-[ExhataQ/Xplayer](https://github.com/ExhataQ/Xplayer/blob/HEAD/electron/popularity.js):
```js
const res = await fetch("https://api.listenbrainz.org/1/popularity/artist", {   // או /release-group
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ artist_mbids: ids })                                   // או release_group_mbids
});
// [{ artist_mbid, total_listen_count, total_user_count }, ...]  (null = אין נתונים)
```
- Xplayer מדרג לפי `total_user_count` על סקאלה לוגריתמית ביחס למועמד הכי פופולרי.
- **ההתאמה למשחק שלנו:** מחפשים ב-MusicBrainz עמוד של כ-100 מועמדים לפי תגית, שולחים POST אחד ל-ListenBrainz עם כל המזהים, ומשאירים את N המובילים.

### 9.4 שירים: הנקודה החלשה
FreeListen מציין במפורש שספירות ההאזנה של ListenBrainz לשיר בודד **מתפזרות על פני כל הגרסאות שלו** (כל MBID נספר בנפרד), ו"יוצאות חד-ספרתיות גם לשירים מפורסמים".

**הפתרון שלהם:**
- מקבצים recordings לפי כותרת ולהקה מנורמלות.
- סוכמים כמה releases כל קבוצה מופיעה בהם. שיר מפורסם מופיע בהרבה אלבומים, אוספים והוצאות.
- המידע הזה מגיע בחינם עם תשובת החיפוש.

**מה לא ידוע:** האם חיפוש recordings לפי תגית ז'אנר מחזיר מספיק תוצאות. זה צריך בדיקה חיה. חלופה: לקחת שירים מתוך רשימת השירים של אלבומים פופולריים בז'אנר, שנמצאו לפי 9.2 ו-9.3.

### 9.5 עוד נתון רלוונטי
[rousseau/rusty-music](https://github.com/rousseau/rusty-music/blob/HEAD/docs/popularite.md) מדד את ListenBrainz על מדגם של 200 שירים אקראיים:
- ל-97% מהם היו נתוני פופולריות.
- הקצב היה בערך בקשה אחת בשנייה, ב-batch-ים של 60.
- **לפי המדידה, ListenBrainz "נוטה לפרוג, מטאל ואינדי"**, וזה מתאים לנו.
